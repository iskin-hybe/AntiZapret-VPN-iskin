# Диагностика и типовые проблемы

_Выжимка из чата проекта (2026-01-01 — 2026-11-05). Актуальное — вверху; устаревшее помечено. Источник: [АВТОР] — автор проекта, [N польз.] — число подтвердивших участников. Номера #NNNNN — id сообщений в выгрузке._

Формат: **симптом** → причина → решение. Универсальный совет автора: «что-то глючит — накати скрипт заново». Если не помогает — чистая Ubuntu 24.04, настройки по умолчанию, без бэкапов и дополнений [АВТОР] (#88683, #94430).

## Подключение к серверу

- **Подключается и через ~10 с рвётся** → IP хостинга или порт в блоке → смените порт (резервные 5xx) или хостера [АВТОР] (#66094, #72146).
- **Из дома нет ни ping, ни SSH, а с хостинга сервер доступен** → бан IP сервера. Трафик не ходит в обе стороны, с сервера недоступны даже DNS в РФ.
  - Трассировка обрывается через 2–4 хопа — это ТСПУ провайдера; если доходит до зарубежных узлов, это не блок.
  - Бан держится около 3–4 недель. Решения: российский прокси (`proxy.sh`) или смена IP [АВТОР + польз.] (#83035, #92778, #95983, #97924, #98521, #93463).
- **Ping проходит, а SSH/OpenVPN/iperf3 нет** → «белый список протоколов» → помогает RU-прокси [АВТОР + 1 польз.] (#92778, #93921, #93463).
- **После захода на некоторые зарубежные IP с домашнего IP блокируются все VPN** («триггер») [АВТОР + 2 польз.] (#65386, #65883, #66107, #68669, #70528).
  - Закрываются 443 TCP/UDP и порты выше 1000, порт 80 остаётся свободен. Блок держится от 10–15 минут до суток с лишним.
  - За CGNAT его может вызвать сосед.
  - Помогали полный VPN и порт 5xx.
- **С одного IP проходит только одно подключение** → особый вид блокировки, решения нет [АВТОР + 1 польз.] (#92868, #99075).
- **OpenVPN TCP не работает** → норма: TCP выключен по умолчанию и виден сканерам. Используйте UDP [АВТОР] (#91454, #93005, #96654).
- **Медиа или скорость плохие только на порту 50443** → причина не установлена. Поставьте первым 443 или 504 [4 польз.] (#91200, #92403, #94930, #94990, #94998).
- **AWG перестала подключаться** → обновите АЗ и конфиг, затем поменяйте `Jc` или задайте новый `I1` [АВТОР + 1 польз.] (#87072, #87079, #92972, #98983).
- **Сервер не отвечает на ping** → так задумано (`SCAN_PROTECTION`) [АВТОР] (#59973, #79970, #94241).
- **Клиенты за промежуточным сервером банятся защитой** → внесите его IP в `allow-ips.txt` [АВТОР] (#89181).
- **АЗ не принимает новые подключения до ребута** → обновите АЗ [АВТОР] (#59886).
- **Debian 12: UDP «висит» 2–4 раза в день** → переустановите на Ubuntu 24 [АВТОР] (#66161).
- **После перезагрузки прокси клиенты не подключаются, хотя службы работают** → переустановите или обновите `proxy.sh` (#93709) (1 польз., не подтверждено).

## Строки в логах OpenVPN

- **Норма, ничего делать не нужно:** `replay-window` (плохой канал), «packet was truncated/expanded» (следствие патча), «AEAD Decrypt error: bad packet ID», «TLS Error: unknown opcode received» [АВТОР] (#62079, #69568, #81070, #91220).
- **CPU openvpn 100%, исходящий канал в потолок, `journalctl | grep 'No buffer space available'`** → баг OpenVPN (issue #1048) → `reboot -f`, затем обновите АЗ [АВТОР] (#86891, #87951, #93863, #98564).
- **Ежедневные ребуты и зависания** → OpenVPN TCP (зависает DCO в ядре) → отключите TCP-службы [АВТОР + 2 польз.] (#83112, #83534, #87980, #91660). Самопроизвольные ребуты одноядерного VPS под нагрузкой (краш ядра) не решены (#70304, #70458).
- **«Failed to stat CRL file»** → права на `easyrsa3/pki`, исправлено в скрипте 23.07 → обновите АЗ (#89823, #89866).
- **«Could not create temporary file /tmp/openvpn…»** → перезапустите `openvpn-server@*` (#95298) (1 польз., не подтверждено).
- **«received data for a non-existing peer», переподключения каждые 2–20 с** → отключите Warper, переустановите OpenVPN, перезагрузитесь (#93881, #93887) (1 польз., не подтверждено).

## Сайты и сервисы

- **Открывается чужой сайт или SSL-ошибка** → старый фейк-IP в кэше → перезагрузите всё [АВТОР] (#58957, #61548).
- **Сайт грузится частично** → добавьте его остальные домены, найти их помогут ipvfoo и PCAPdroid [АВТОР] (#68239, #68244).
- **Загружается ~16 КБ и обрывается** → заблокирован IP хостинга сайта → пустите сайт через АЗ [АВТОР] (#84549, #85558, #88913).
- **Сайты на Cloudflare без стилей** → подсети 8.x в маршрутах Cloudflare и флаг LNA в Chrome [АВТОР] (#60046, #60059).
- **Сайт за CDN банит IP сервера** → его подсети в `exclude-ips.txt` + doall, или RPZ [АВТОР] (#59692, #59693).
- **Сайт не открывается только в АЗ** (ea.com на Akamai) → провайдер блокирует IP, которые отдал DNS АЗ → пишите провайдеру [АВТОР + 1 польз.] (#96678, #96703).
- **На маркетплейсах нет картинок / домен резолвится в `0.0.0.0`** → адблок АЗ → `exclude-adblock-hosts.txt` или отключите `ANTIZAPRET_ADBLOCK` [АВТОР + 3 польз.] (#70795, #99509, #101019).
- **Не открывается cloudflare.com** → заблокирован намеренно (cdn-cgi/trace показывает IP) → WARP или passthru на свой риск [АВТОР] (#97454, #100393, #100733).
- **Gemini «недоступен в стране»** → Google видит IP WARP или VPS как российский → см. [routing-and-lists.md](routing-and-lists.md#рецепты-по-сервисам) [АВТОР + 3 польз.] (#92049, #93943, #97031).
- **Win 11 «нет интернета»** → NCSI проверяет по IPv6, ни на что не влияет [АВТОР] (#59748).

## WARP

- **В АЗ периодически отваливаются Gemini/YouTube, а полный VPN работает** → подвисает WARP → обновитесь: исправления от 27.10 (TCP timestamps) и 02.11 [АВТОР + 2 польз.] (#97018, #98252, #99702, #100591).
- **WARP в логе «connected», а трафик не идёт** → смотрите `journalctl -u antizapret` [АВТОР] (#90320, #90324).
- **WARP не поднимается, в конфиге пустой endpoint** → API WARP не ответил, и WARP protection штатно блокирует трафик [АВТОР] (#94619).
- **С WARP не открываются сайты (Habr и др.)** → MTU → задайте MTU WARP 1280 [АВТОР + польз.] (#75064, #75139, #94747, #94824).
- **Warper пишет об «активных правилах AntiZapret WARP»** → выключите WARP в АЗ и перезапустите `up.sh` (#91986) (1 польз., не подтверждено).

## Telegram и WhatsApp

- **Зависают медиа в Telegram** (чаще на телефоне с OpenVPN АЗ в мобильной сети). Полностью не решено [АВТОР] (#86403, #87003, #87179, #87383).
  - 21.06 и 02.07 правили conntrack и `tcp_tw_reuse`.
  - Дополнительно: отключите прокси в Telegram и сверьте настройки IPv6 на устройствах.
- **Telegram висит на хостерах, где `91.105.192.x` (DC203, медиа) недоступен** (H2 и др., маршрут через перегруженный Хельсинки) → Telegram уходит на IPv6 и зависает → на H2 помог WARP режим 2 для АЗ [АВТОР + 3 польз.] (#94605, #94718, #94835, #95124, #94710).
- **Telegram через АЗ не соединяется, через полный VPN работает** → проверьте на VPS `nc -vz api.telegram.org 443`. Если не отвечает — проблема у хостера. Ещё попробуйте без DCO и не на порту 50443 (#91310, #91704) [1 польз.].
- **iPhone через Keenetic не грузит Telegram** → отключите IPv6 в локальной сети [АВТОР] (#70146).
- **Не работают звонки WhatsApp** → звонки идут мимо маршрутов, через маршрут по умолчанию. Через роутер работают, на телефоне надёжного решения нет [АВТОР] (#94303, #64707).
- **После обновления IP-списков TG/WA не работают на роутере или в WG** → скачайте маршруты и профили заново [АВТОР] (#63532, #90559, #91723).

## Скорость и MTU

- **Сайты висят, Google/GitHub не грузятся только на мобильном (МТС, Мегафон) или через прокси** → MTU/MSS → уменьшите MTU в профиле или включите на сервере MSS clamp: `iptables -t mangle -A POSTROUTING -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --set-mss 1360` [2 польз.] (#98154, #99003, #99515).
- **Скорость сервера около нуля, apt не работает, ping идёт** → PMTU blackhole у хостера: большие пакеты пропадают молча. Проверка: `ping -M do -s 1336 8.8.8.8`, увеличивать размер до первой потери; потом снизить MTU интерфейса сервера. В Литве и Латвии у 4VPS проходило не больше 1364 байт, MTU 1358 вернул ~1 Гбит [5+ польз.] (02–03.26, 4VPS #40125, #40159, #40563).
- **MTU сейчас** с 27.10 установщик определяет сам (1280–1420), для WARP он задаётся отдельно (`WARP_MTU`). Раньше всегда стоял 1420, при «Low MTU 1448» советовали 1368. Подробнее — в [protocols.md](protocols.md) [АВТОР] (#87129, #98132, #99702).
- **Низкая скорость на одноядерном VPS** → упирается в CPU (OpenVPN) → проверьте `sysbench cpu run --threads=1`. OpenVPN 2.7 с DCO ест заметно меньше CPU [АВТОР + 1 польз.] (#82466, #92335).
- **VDSina: медленный UDP или исходящий TCP** → отключённые TSO/GSO → для теста `SEGMENTATION_OFFLOAD=on` в setup и ребут [АВТОР, не проверено] (#85536, #85566). В 03.26 автор советовал просто сменить хостинг (#66739).
- **Ростелеком вечером: потери до NL/FR/DE** → шейпинг на стыке → иногда помогает смена IP или подсети [3–4 польз.] (#99749, #99817, #100226).
- **Роутер без AES-NI** → `CHACHA20-POLY1305` в `.ovpn` [АВТОР] (#99378).

## Как мерить и проверять

- **Скорость через АЗ** проверяйте на speed.cloudflare.com: обычный спидтест идёт мимо АЗ [АВТОР] (#61385).
- **iperf3** [2 польз.] (#92338, #92339, #95508):
  - на сервере: `apt install iperf3`, откройте порт 5201 в iptables, запустите `iperf3 -s`;
  - на клиенте: `iperf3 -c <шлюз> -R`, где шлюз `10.29.0.1` для АЗ и `10.28.0.1` для полного VPN; для UDP добавьте `-u -b 50M -l 1200`;
  - затем повторите без VPN на внешний IP и посмотрите потери через `ping`.
- **Статус OpenVPN** (файл статуса по умолчанию выключен, включается опцией `OPENVPN_LOG`): `echo "status" | socat - UNIX-CONNECT:/run/openvpn-server/antizapret-udp.sock` (для полного VPN — `vpn-udp.sock`). Опрашивайте нечасто, иначе OpenVPN может упасть [АВТОР] (#90938, #90941, #99361).
- **Версия OpenVPN и DCO:** в `openvpn --version` должна быть `[DCO]`, а строка «DCO version» не должна быть N/A [АВТОР] (#69172, #97922).
- **DNS:** `dig <домен> @127.1.1.1` (АЗ) / `@127.2.2.2` (VPN), `systemctl status kresd@1`, `tcpdump -i any -n src host <VPN-IP клиента> and port 53`. На клиенте `ping <домен из списка>` должен вернуть фейковый IP. Подробнее — в [dns.md](dns.md#отладка) [АВТОР] (#68500, #75155, #88037).
- **Журналы:** `journalctl -u antizapret` (запуск и WARP), `journalctl | grep 'No buffer space available'` (баг #1048). Логи OpenVPN — `verb 4–5`; файлы больше 100 МБ в `/etc/openvpn/server/logs` doall удаляет ежедневно [АВТОР] (#70390, #86891, #90320).
- **WARP:** подключение идёт через маршрут по умолчанию — `ip route get $(dig engage.cloudflareclient.com +short)`; какой MTU пролезает — циклом `ping -I warp-antizapret -M do -s <размер>` [АВТОР] (#96635, #99644).
- **Доступность сервера снаружи:** traceroute (где обрывается), platform.censys.io (снаружи должен быть виден только порт 22), check-host.net, cheburcheck.ru. Онлайн-чекеры ТСПУ ненадёжны: при белом списке на порт покажут 0, хотя всё работает [АВТОР + польз.] (#64013, #91321, #94933, #95725, #99305).
- **С VPS:** `nc -vz api.telegram.org 443` — доступен ли Telegram (#91310); узел кэша Google — `redirector.googlevideo.com/report_mapping?di=no` [АВТОР] (#60871).
- **Какие домены использует сайт:** ipvfoo (ПК), PCAPdroid (Android); для Discord — сборка PTB, `Ctrl+Shift+I`, фильтр «Creating connection to» [АВТОР] (#84474, #89544, #91845).
