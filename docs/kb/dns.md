# DNS

_Выжимка из чата проекта (2026-01-01 — 2026-11-05). Актуальное — вверху; устаревшее помечено. Источник: [АВТОР] — автор проекта, [N польз.] — число подтвердивших участников. Номера #NNNNN — id сообщений в выгрузке._

## Как устроен DNS АЗ

- **Резолвер.** На сервере работает Knot Resolver (`kresd`). АЗ перехватывает запросы клиента на любой IP, поэтому в клиенте подойдёт любой рабочий DNS, но указать его нужно обязательно. DNS, заданный на роутере, на DNS АЗ не влияет [АВТОР] (#77677, #99671).
  - На устройствах автор ставит 1.1.1.1 или 8.8.8.8. Чужие DNS режет только АКАДО, и то не везде; там используйте DNS провайдера [АВТОР; 1 польз. оспорил] (#59626, #61930).
- **Локальные адреса резолверов:** `127.1.1.1` — АЗ, `127.2.2.2` — полный VPN, `127.3.3.3` — прокси.
  - 06.06 они заменили `127.0.0.x`, потому что конфликтовали с bind9, который ставит ISPmanager [АВТОР] (#84329).
  - 20.02 локальный DNS отвязан от tun: так устранили SERVFAIL на 1–2 с под нагрузкой [АВТОР] (#66368).
- **Фейковые IP.** Домены из списков DNS отдаёт как адреса из фейковой подсети, а сервер транслирует их в реальные.
  - Сейчас (`ALTERNATIVE_FAKE_IP=y`, по умолчанию с 08.04) это `198.18.0.0/15`. При `n` используется `10.30.x` (или `172.30.x` при `ALTERNATIVE_CLIENT_IP=y`) [АВТОР] (#76434, #76839).
  - История: 28.01 появился альтернативный диапазон 198.18.0.0/15. Браузеры (PNA) не считают его локальным, а клиенты тогда переезжали в 172.x. Сейчас диапазон клиентов и диапазон фейк-IP — две отдельные опции [АВТОР] (#61524, #61713).
  - Если роутер или AWG-клиент настроен на старые адреса, при переустановке ответьте `N` или обновите профили. OpenVPN-профили обновлять не нужно [АВТОР + польз.] (#61713, #76839).
- **IPv6 в АЗ не используется.** Он ломает фейк-IP, поэтому AAAA-записи не отдаются. С 03.06 для заблокированных AAAA возвращается `::`, а не `100::1` [АВТОР] (#67059, #83939).
  - Подключаться к серверу по IPv6 можно: удалите `/etc/sysctl.d/99-disable-ipv6.conf` и перезагрузитесь. Пускать IPv6 внутрь VPN автор не планирует (#92306, #96299, #100941).
  - 03.11 блокировка записей HTTPS/SVCB ломала сайты по `http://`, вернули прежний механизм [АВТОР] (#100754).
  - Spotify через Music Assistant получает на AAAA ответ `::` и стучится на `::1`. Помогает отдавать NODATA, в AdminPanelAZ для этого есть переключатель (#96485, #96711) [польз.].
- **Hostname сервера.** Если hostname совпадает с доменом подключения, DNS АЗ отдаёт по нему IP шлюза (10.29.x). Тогда клиенты за роутером с АЗ не могут подключиться к серверу. Смените hostname [АВТОР] (#69887, #90508).
- Зоны private/local/test DNS АЗ обслуживает сам, запросы `*_*.arpa` отсекает [АВТОР] (#60123, #61072).

## Выбор резолверов

- **Текущее меню `ANTIZAPRET_DNS`** (setup.sh): 1 MSK-IX+NSDI (+BI.ZONE, TransTeleCom, Cloudflare, Quad9, ControlD, UltraDNS) — по умолчанию; 2 Cloudflare+Quad9 (+ControlD, UltraDNS); 3 Yandex\*; 4 Google\*; 5 AdGuard\*; 6 Comss\*\*; 7 GeoHide\*\*. Звёздочка — с EDNS Client Subnet, две — с проксированием, скрывают IP сервера. Для полного VPN (`VPN_DNS`): 1 — свой резолвер, как у АЗ; 2 — Cloudflare/свой DNS. 11.08 апстримов стало 8 вместо 4 [АВТОР] (#91624).
- **Для АЗ нужны RU-резолверы** или ECS с российским IP, иначе RU-сайты получают неверные IP [АВТОР] (#84326). Cloudflare и Quad9 в 01.26 выбрали потому, что они не передают IP клиента (Google и Яндекс передают). Из-за этого tmdb отдавал 127.0.0.1 «российским» клиентам [АВТОР] (#61770, #61786).
- С московского сервера ответы обычных DNS подменяются [АВТОР] (#97146).
- **DNS с проксированием (Comss, GeoHide)** нужны, если Google определяет IP сервера как РФ: для Gemini, AI Studio и т. п. Если VPS числится в РФ, других решений нет [АВТОР] (#68395, #66466).
  - 02.09 Malw заменили на GeoHide. 10.10 Xbox DNS убрали из меню после давления РКН [АВТОР] (#93801, #98028, #98746, #98787).
  - С 29.09 такие DNS не участвуют в fallback: либо работают они, либо ничего [АВТОР] (#97146, #97187).
  - Противоречие: в 01.26 автор Comss не рекомендовал («не обходит Gemini», #59780), а с 03.26 называл его среди DNS, которые помогают с Gemini (#68395).
  - eu.geohide неверно резолвит RU-домены (#99492). С GeoHide приложение ChatGPT на iOS выдаёт SSL-ошибку ISRG Root X2, при этом браузер и Android работают (#99606) (1 польз., не подтверждено).
- **SkyDNS не использовать** (03.11): у него лимиты, можно получить бан, а настройки по умолчанию и так корректны [АВТОР] (#100804).
  - История: 14.01 НДСИ в настройке по умолчанию заменили на SkyDNS — НДСИ перестал резолвить WhatsApp и YouTube (#59998, #63636); 26.01 появилась опция «только SkyDNS» с обязательной регистрацией и привязкой IP (#61072, #62166, #63081); 05.03 по умолчанию вернули MSK-IX и НДСИ (#68663); 11.08 SkyDNS убрали из-за претензий к коммерческому использованию и банов IP (#91624, #91655).
  - SkyDNS отдавал российские узлы Akamai и Fastly (#61227). На Aeza DE пользователю в 05.26 SkyDNS вернул резолв RU-доменов (#83655) [1 польз.].
- MSK-IX и НДСИ не резолвили zendesk.com и его CNAME (02.26, #62102). Актуально ли это после появления fallback, не проверено.
- **Сменить DNS без переустановки:** поправьте IP в конфиге kresd и перезапустите его. Новые DNS-опции и модули приходят только с установкой. DNS провайдера VPS как апстрим не работает [АВТОР] (#75238, #68723, #62159).

## fallback.lua

- Модуль переспрашивает запасные DNS при плохом ответе основных. В текущем коде запасные — Cloudflare, Quad9, ControlD, UltraDNS, OpenDNS и DNS4EU.
- История [АВТОР]:
  - 01.26 fallback не было, проблемные домены (tracker.openbittorrent.com, ntc.party, tmdb) прибивали к IP через RPZ (#61827, #62805);
  - 20.02 удалён модуль `fallback_tcp` (#66368);
  - 05.03 появился модуль fallback (#68663);
  - 26.03 — `fallback.lua`: переспрашивал CF, Quad9, Yandex и SkyDNS при любом ответе, кроме NOERROR, например при ложном NXDOMAIN для whatsapp.com (#72578);
  - 13–14.07 добавлен переход при NOERROR без A-записи и при SERVFAIL; эта версия раскатилась первым запуском doall (#88695, #88781);
  - 31.07 добавлен переход при таймауте всех основных серверов и резервные порты; эта версия приходит только с переустановкой (#90593, #90610).

## Кэш

- Сейчас минимальный TTL кэша — 5 минут (в `kresd.conf` `min_ttl = 300`, max — сутки). Кэш сбрасывается при рестарте kresd и при `doall.sh`; `doall.sh noclear` запускает без сброса [АВТОР] (#60502, #95738, #99904).
- История [АВТОР]: 03.06 DNS упрощён — без префетча и протухшего кэша, рекламным доменам TTL 24 ч (#83939); 11.08 минимальный кэш поднят примерно до 1,5 ч (#91624); 27.10 снова 5 минут из-за CDN с часто меняющимися IP (#99904). В сообщении от 27.10 сказано «вместо 30», и с объявленными 1,5 ч это не сходится — расхождение не прояснено.
- В кэше устройства или роутера остался старый фейк-IP → чужой сайт или SSL-ошибка. Перезагрузите всё. Сразу после установки подождите пару минут, пока скачается список, иначе роутер закэширует реальный IP [АВТОР] (#58801, #58957, #61548).

## DoT/DoH и DNS через WARP

- DoT и DoH с АЗ не работают, поэтому на устройствах отключайте «частный/безопасный DNS». Транзитный DoT/DoQ (порт 853) блокируется, DoH/DoT ещё и по домену [АВТОР] (#62229, #66551, #97232, #99904).
- Опция `DNS_WARP` («Route all DNS outbound queries via Cloudflare WARP», с 11.10) отправляет все исходящие DNS-запросы через WARP. Нужна, если IP сервера забанен и RU-резолверы недоступны [АВТОР] (#98132, #98137).
- В AmneziaVPN 5.0 DNS Cloudflare из настроек приложения перекрывают DNS из конфига (#91464) (1 польз., не подтверждено).

## Свои переопределения: custom.lua и RPZ

- `/etc/knot-resolver/custom.lua` (АЗ) и `custom2.lua` (полный VPN), с 11.08. В коде есть ещё `custom3.lua` (прокси). Через них задаётся свой апстрим для отдельных доменов. Файлы попадают в бэкап [АВТОР] (#91624, #91655, #93801, #99233, #99234).
- Привязать домен к IP можно через RPZ. Так держали t.me, когда его домен заморозили (14.07). Сторонний antizapret-dns-overrides делает то же самое [АВТОР] (#85338, #85341, #88723).
  - Файлы в `config/`: `deny-rpz.txt` / `deny2-rpz.txt` / `deny3-rpz.txt` — блок для АЗ / полного VPN / прокси (`CNAME .` даёт `0.0.0.0`); `proxy-rpz.txt` — пустить через АЗ; `warp-rpz.txt` — пустить через WARP. Раньше (01.26) был `config/rpz.txt` с форматом «домен A ip» (#59692, #59693).

## Что DNS АЗ блокирует намеренно

- **Реклама и трекеры.** `ANTIZAPRET_ADBLOCK` (по умолчанию `y`) и `VPN_ADBLOCK` (по умолчанию `n`) с 05.08 заменили `BLOCK_ADS`. Правила — AdGuard и OISD [АВТОР] (#91259).
  - Ответ `0.0.0.0` означает блок; исключение — через `exclude-adblock-hosts.txt` [АВТОР] (#70795, #80772).
  - Если на маркетплейсах нет картинок, начните с этого [3 польз.] (#99509, #101019).
- **Трекеры VK и др.** vk-analytics.ru, trace-flow.ru, apptracer.ru, reef.vk-cdn.net; в полном VPN ещё oneme.app и rustore.ru (18.05, 12.06) [АВТОР] (#82029, #85321).
- **Сервисы «узнать свой IP»**, которыми приложения (Max и др.) выясняют IP сервера: api.ipify.org, checkip.amazonaws.com, api.myip.com, api.2ip.ua, а через deny.rpz — iplocation.io, decodo.com, nordvpn.com и др. Блокировку oneme.ru, max.ru и telega.info сняли 16.04: приложения кешируют IP [АВТОР] (#68617, #75707, #78386, #95697, #96885).
- **cloudflare.com и www.cloudflare.com** заблокированы с 26.09: страница `cdn-cgi/trace` показывает IP. Маршруты по IP Cloudflare при этом работают. Обход на свой риск — passthru в deny.rpz или пустить Cloudflare через WARP [АВТОР + польз.] (#97454, #100393, #100724, #100728, #100733).

## Отладка

- На сервере [АВТОР] (#66368, #68500, #68627, #75155, #84329):
  - `dig <домен> @127.1.1.1` (АЗ), `@127.2.2.2` (полный VPN), `@127.3.3.3` (прокси); до 06.06 — `127.0.0.x`;
  - `systemctl status kresd@1`;
  - `tcpdump -i any -n src host <VPN-IP клиента> and port 53` — доходят ли запросы клиента.
- После переезда на новый хостинг YouTube резолвился в реальные IP или в NXDOMAIN. Помог `systemctl restart kresd@1 kresd@2` (#94177) [1 польз.].
- На клиенте:
  - `ping x.com` (или другого домена из списка) должен ответить фейковым IP (198.18.x / 10.30.x), иначе DNS идёт мимо АЗ [АВТОР] (#61066, #88037);
  - nslookup к внешнему DNS отдаёт заглушку РКН → DNS не завёрнут в VPN; googlevideo резолвится в реальный IP → DNS АЗ не настроен на устройстве [АВТОР] (#59927, #61022).
- Реальный IP за фейковым в 01.26 смотрели через `iptables-save` (#62127). С 02.11 фейк-IP обрабатываются через nftables, и этот способ мог устареть (не проверено).
- Сайт не открывается только в АЗ (пример — ea.com на Akamai): DNS АЗ мог отдать IP, которые блокирует провайдер. Пишите провайдеру, у пользователя заявку приняли [АВТОР + 1 польз.] (#96678, #96703).
- 05.03 исправлено: при «route all except RU» не резолвились Госуслуги (policy.PASS в Knot Resolver) [АВТОР] (#68518).
- Не решено:
  - macOS/Safari за роутером не открывает заблокированные сайты; совет — переустановка с диапазоном 198.18.0.0/15 (#96278);
  - в новой версии с ПК сайты через фейк-IP не работали при обоих диапазонах (#100279) (1 польз., не подтверждено).
