## Принципы

- **Лёгкость.** АЗ должен жить в 1 ГБ RAM, поэтому AdGuard Home (~2 ГБ) не будет (#64871).
- **Обновление — только повторным setup.sh.** «Что-то глючит — накати скрипт заново»; универсальное лечение — чистая Ubuntu 24.04, настройки по умолчанию, без бэкапов и допов. Пакеты и ОС в обход setup.sh не обновлять (#87402 #88683 #90645 #94430).
- **Без автообновления установки** («утром сервер будет трупом»), без неинтерактивного режима, старых версий и тегов (#69446 #76592–76595 #79932 #89381).
- **Списки:** в общий список — только популярное; бесплатно можно попросить добавить до 5 сайтов; мусорные домены (Xiaomi, duckdns, haylou) не добавляет. «Google рано или поздно заблокируют» — поэтому его домены в АЗ (#60679 #61665 #75358 #78222).
- **IP-списки:** добавлять IP только для сервисов, которые ходят по IP (Telegram, WhatsApp, Discord), без пересечения с RU. Бездумные IP повышают риск бана. Подсети хостеров больше не обновляет, актуальны только Telegram, WhatsApp и Cloudflare (#67639 #68155 #68158 #96692 #99015).
- **Снаружи должен быть виден только SSH (порт 22)**, проверка через censys. Не выставлять наружу веб-панели, чужие сертификаты, telemt, WhatsApp-прокси, StatusOpenVPN на 8081. Сервис на 443 с сертификатом Яндекса, Google или Max сканер распознаёт легко (#69724 #95725 #95928 #97504 #100931).
- **Защита SSH:** fail2ban тяжёлый, лучше sshguard или правила iptables; внешние блок-листы сканеров бесполезны. В deny-ips автор себе внёс только подсети ФГУП ГРЧЦ (AS61280, AS213853) (#75742 #77132 #80800 #81966 #93732 #94241).
- **Хостинг:** VPN ставить на серверы, которые не жалко потерять; для тестов — посуточная оплата; торренты ведут к абузам; SMTP хостеры закрывают. DNS доменов держать за рубежом (#83680 #84871 #86139 #87198 #100692).

## Рекомендации против блокировок (актуальные)

- Полный VPN — только через WARP; не добавлять в АЗ лишние IP; не включать OpenVPN TCP. WARP снижает вероятность бана (24.08, 04.11; #93005 #100979).
- Через АЗ IP сервера почти не виден; для полного VPN скрыть IP сервера может только WARP, RU-прокси его не скрывает (#68667 #75547 #75686).
- RU-прокси — «не панацея»: если основной IP забанен, с RU-хостингов до него тоже не достучаться. Прокси брать там же, где основной сервер, АЗ и прокси — на разных серверах; формулировку в README надо поменять (#95763 #95948 #96427 #99739).
- Реклама YouTube DNS'ом не убирается — uBlock Origin Lite (#70517 #84574 #93345). SkyDNS не использовать: лимиты, можно словить бан (#91655 #100804).

## Отказы («не будет» / «не планируется»)

- **IPv6 внутри VPN** — нет: двойной стек сложно поддерживать, IPv6 ломает fake IP. Подключаться к серверу по IPv6 можно: удалить `/etc/sysctl.d/99-disable-ipv6.conf` и перезагрузиться. 04.11 записал как хотелку, без обещаний (#67059 #92306 #96299 #98029 #100941).
- **sing-box и маршрутизация доменов по разным выходам** — не планируется (#64864 #65892 #75569 #77902 #100941). При этом выборочный WARP по доменам сделан 27.08.
- **AdGuard Home**, автообновление установки — нет. Разделять изоляцию клиентов и сервера — не будет (#64871 #67266).
- Подсеть Apple 17.0.0.0/8 не добавляет (#91400). Удаления у proxy.sh и telemt нет (#90714). АЗ на RU-сервере сам не делал (#90351).
