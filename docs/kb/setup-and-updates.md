# Установка, обновление, бэкап

_Выжимка из чата проекта (2026-01-01 — 2026-11-05). Актуальное — вверху; устаревшее помечено. Источник: [АВТОР] — автор проекта, [N польз.] — число подтвердивших участников. Номера #NNNNN — id сообщений в выгрузке._

## Требования к серверу

- **ОС:** минимум Ubuntu 24 или Debian 13 (с 08.04; Debian 11 убран 15.03). На Debian 12 ядро остаётся 6.12 без DCO («DCO version: N/A»), исправлять не будут; там же АЗ по UDP «висел» 2–4 раза в день — лечилось переустановкой на Ubuntu 24 [АВТОР] (#66161 #70130 #76442 #76451 #76858). OpenVZ и LXC setup.sh не принимает (по коду форка).
- **Рекомендуемая ОС — Ubuntu 24.04.** Универсальное лечение: чистая 24.04, настройки по умолчанию, без бэкапов и допов [АВТОР] (#87402 #88683). Совет брать Debian 13 из-за snap [1 польз., не подтверждено] (#91502) неактуален: setup.sh сам удаляет snapd (по коду форка).
- **Ubuntu 26.04 — противоречиво.** 26.05–03.07 автор: не поддерживается (нет пакета knot-resolver, knot-resolver6 — другой, несовместимый продукт) (#83062 #83065 #87695). С 22.09: проверена и работает, но свои серверы автор держит на 24.04 — там через HWE тоже ядро 7+, разница минимальна [АВТОР] (#95708 #96940 #98133 #100629). Участники: обновление 24.04→26.04 на месте дало лаги, на свежей 26.04 (Veesp) не подключался OpenVPN [2 польз.] (#98632 #98645 #100057). Сейчас setup.sh подключает репозиторий knot-resolver от CZ.NIC (по коду форка).
- **CPU и RAM:** 1 ядро + 1 ГБ на 15–20 человек, если кроме АЗ ничего нет; для >1 Гбит/с нужно больше ядер [АВТОР] (#61357 #64128 #65886). АЗ + AdminPanelAZ (профиль standard без планировщика CIDR) влезают в 1 ГБ, с чем-то ещё нужно 2–4 ГБ [1 польз., не подтверждено] (#91502). На дешёвом одноядерном VPS скорость часто упирается в CPU (OpenVPN), проверка `sysbench cpu run --threads=1` [1 польз., не подтверждено] (#92335). OpenVPN 2.7 с DCO заметно легче для CPU [АВТОР] (#82466).
- **Swap:** если swap нет, создаётся 1 ГБ; существующий не трогается [АВТОР] (#92285 #98082).
- **Диск:** нужно не меньше 2 ГБ свободного места, установка реально съедает около 2 ГБ, проверку не обходить [АВТОР] (#71485 #92285 #95622). С 05.06 установщик до проверки чистит журналы, /var/log и кэш apt: у многих логи занимали 10–20 ГБ (#84285 #90047).
- **Домен:** при установке нужен домен с A-записью IPv4 (#66279). Домен в профилях вместо IP удобнее: при смене IP достаточно поправить A-запись, хотя ПК может какое-то время держать старую запись в кэше [АВТОР + 3 польз.] (#81960 #96544 #96545 #100138 #100141). DNS домена держать за рубежом: 02.11 Beget лёг целиком вместе с DNS [АВТОР] (#100692).
- **hostname не должен совпадать с доменом подключения:** иначе DNS АЗ отдаёт по нему IP шлюза (10.29.x), и клиенты за роутером с АЗ не подключаются. Решение — сменить hostname или отключить изоляцию [АВТОР] (#67255 #69887 #90508).

## Установка

- Установка не стартует, пока работают фоновые apt/unattended-upgrades или система ждёт перезагрузки: подождать или перезагрузиться [АВТОР + 1 польз.] (#58791). Проверка встроена в setup.sh (по коду форка).
- Обновление ядра во время установки может идти 20–30 минут [АВТОР] (#92271). 02.09: git clone требовал логин GitHub (HTTP 401), в скрипт добавлен `git config --global http.version HTTP/1.1` [АВТОР + 1 польз.] (#93810 #93811).
- После установки сервер сначала скачивает списки. Если подключиться раньше, в кэш роутера попадут реальные IP — подождите пару минут [АВТОР] (#58801).
- OpenVPN UDP/TCP и WireGuard выбираются в установщике, TCP по умолчанию выключен (03.06; #83939). Флаги `*_ENABLE` в файле setup не применяются, переключать вручную: `systemctl enable|disable --now openvpn-server@antizapret-tcp` и `openvpn-server@vpn-tcp` [АВТОР] (#86152 #86153).
- Вопрос «Restrict forwarding … to forward-ips/route-ips» — оставить по умолчанию [АВТОР] (#100795).
- Если вы подключены к серверу через этот же АЗ, SSH при обновлении оборвётся: обновлять через другое подключение. Зависание на удалении TCP-службы лечилось повторным запуском и ещё одним ребутом [2 польз.] (#91651 #92270).
- proxy.sh запущен по ошибке: до строки «Installation, please wait...» ничего не меняется, после — проще переустановить ОС; удаления у proxy.sh и telemt нет [АВТОР] (#85644 #85651 #90714).
- Исправленные сбои установки (для справки): не было пакета ethtool, пропадал jq (ломал WARP), мешал archive.debian.org (#68180 #68592 #69205); 13.06 `dpkg --configure -a` и `apt-get install -f` перенесены в начало скрипта (#85412) [АВТОР].

## Обновление

- **Обновление = повторный запуск setup.sh поверх установленного.** Ключи, профили и настройки сохраняются, клиентские конфиги менять не нужно. «Что-то глючит — накати скрипт заново»; если ставили очень давно, лучше с нуля [АВТОР] (#58778 #58811 #60167 #68723 #94430 #96572 #96653).
- Неинтерактивного режима, старых версий и тегов нет. Автообновления установки не будет: «утром сервер будет трупом» [АВТОР] (#69446 #76592–76595 #79932 #89381 #91645). Можно ли подать сохранённые ответы для «тихого» обновления — вопрос остался без ответа (#101038).
- **Не обновлять пакеты и ОС в обход setup.sh:** апгрейд (например, kresd) затирает настройки и патчи [АВТОР] (31.07; #90645 #90650). Перед обновлением полезен снапшот VPS [1 польз., не подтверждено] (#99957).
- **Что обновляется само (ночью):** только списки доменов и IP, а также сами update.sh, parse.sh и doall.sh (самообновление с 20.01) [АВТОР] (#60502 #64215 #68723 #89381). В этом форке они берутся из `iskin-hybe/AntiZapret-VPN-iskin` (`SCRIPTS_REPO`, `LISTS_REPO` в update.sh). Новые опции, модули DNS, up.sh, конфиги OpenVPN/WireGuard и systemd приходят только через setup.sh.
  - Пример границы: fallback.lua версии 13–14.07 раскатился первым запуском doall, версия 31.07 — уже только установкой [АВТОР] (#88695 #90593 #90610).
- `doall.sh noclear` применяет списки без сброса DNS-кэша, обычный doall кэш чистит [АВТОР] (#60502 #95738).
- Сбои ночного обновления: 17.08 — ошибки 429/503/522 от raw.githubusercontent.com, временно на стороне GitHub [2 польз.] (#92472 #92494); 28.10 — падение на `idn --no-tld` из-за невалидного домена в списке, исправлено в списках [АВТОР] (#99929 #99953); 02.11 — падение на `sysctl -p`, см. «Ядро 7».

## Файл /root/antizapret/setup

- Ответы установщика сохраняются в `/root/antizapret/setup`. Многие можно менять без переустановки и затем перезагрузить сервер, например `CLOUDFLARE_INCLUDE=n`, `TELEGRAM_INCLUDE`, WARP-переменные [АВТОР] (#65200 #87586 #90391 #92426). Не применяются: флаги `*_ENABLE` (см. выше) и DNS — конфиг kresd пишется только при установке; чтобы сменить DNS без переустановки, поправьте IP в конфиге kresd и перезапустите его [АВТОР] (#62157 #75238).
- Переменные (по коду форка на 05.11): `MTU`, `WARP_MTU`, `OPENVPN_PATCH` (1–4), `OPENVPN_DCO`, `ANTIZAPRET_WARP` (1–4), `VPN_WARP` (1–3), `DNS_WARP`, `WARP_PROTECTION`, `ANTIZAPRET_DNS`, `VPN_DNS`, `ANTIZAPRET_ADBLOCK`, `VPN_ADBLOCK`, `ALTERNATIVE_CLIENT_IP`, `ALTERNATIVE_FAKE_IP`, `OPENVPN_BACKUP_UDP`, `OPENVPN_BACKUP_TCP`, `WIREGUARD_BACKUP`, `OPENVPN_DUPLICATE`, `OPENVPN_LOG`, `SSH_PROTECTION`, `ATTACK_PROTECTION`, `SCAN_PROTECTION`, `TORRENT_GUARD`, `RESTRICT_FORWARD`, `CLIENT_ISOLATION`, `OPENVPN_HOST`, `WIREGUARD_HOST`, `ROUTE_ALL`, `*_INCLUDE`, `RECONNECT_WARP`, `CLEAR_HOSTS`, `TXQUEUELEN`.
- Свои ключи WARP: `ANTIZAPRET_WARP_*` и `VPN_WARP_*` (по коду ещё `DNS_WARP_*`) — `PRIVATE_KEY`, `PUBLIC_KEY`, `ENDPOINT`, `ADDRESS`. Для АЗ и полного VPN нужны два разных ключа, после правки — ребут [АВТОР] (17.08; #92426 #92872).
- Служебные переменные: `DEFAULT_*`, `*_OUT_*`, `CLIENT_IP`, `FAKE_IP` [АВТОР] (#77524), см. «Несколько IP».
- История: 19.02 — `OPENVPN_BACKUP_TCP/UDP`, `WIREGUARD_BACKUP`; 12.04 — `WARP_OUTBOUND` заменён на `ANTIZAPRET_WARP` + `VPN_WARP` (тогда y/n, сейчас номер режима); 16.04 — `TXQUEUELEN=1000`, `MTU=1420`, `SEGMENTATION_OFFLOAD=off`; 05.08 — `BLOCK_ADS` заменён на `ANTIZAPRET_ADBLOCK` + `VPN_ADBLOCK` [АВТОР] (#66311 #77475 #78298 #91259). Сейчас в коде `TXQUEUELEN=10000`, а `SEGMENTATION_OFFLOAD` и вызова ethtool нет, поэтому совет от 15.06 ставить для VDSina `SEGMENTATION_OFFLOAD=on` (#85566) устарел (по коду форка).

## Несколько IP и выходной IP

- `ANTIZAPRET_OUT_IP` / `VPN_OUT_IP` и `*_OUT_INTERFACE` (с 22.04) задают выходной IP и интерфейс; входящие подключения на эти IP блокируются. IP для входа должен быть основным в /etc/network/interfaces. 26.09 при заданных выходных IP автор советовал отключать WARP [АВТОР] (#79212 #84140 #96318 #96611 #99440).
- Маршруты на нестандартный выходной интерфейс (например, xray0) сами не добавляются, участник прописал `ip rule`/table вручную [АВТОР + 1 польз.] (#75309 #75321). Трафик АЗ с RU-VPS через wg-туннель на зарубежный VPS заработал без ip rule [1 польз., не подтверждено] (#79239).
- Зачем разносить: чтобы не «сжигать» входной IP, автор предлагал 2 IP на сервере [АВТОР] (#96598). Опыт: выходной сервер забанили, входной через неделю жив [1 польз., не подтверждено] (#96589–96601). Против геоблоков сервисов второй IP на том же VPS не поможет — AS та же [АВТОР] (#70382).
- Смена IP зарубежного сервера: докупить IP, поправить netplan и `remote` в конфигах [1 польз., не подтверждено] (#96088). С доменом в профилях достаточно сменить A-запись.

## Бэкап, восстановление, перенос

- `/root/antizapret/client.sh 8` делает бэкап (`backup*.tar.gz`), пункт 9 восстанавливает без переустановки (с 20.07) [АВТОР] (#89551 #96550). В бэкап попадают custom-up.sh и custom*.lua Knot Resolver [АВТОР] (#88075 #99234).
- Перенос: на чистой ОС положить бэкап в /root и запустить setup.sh. Переустановка 24.04 вместе с восстановлением заняла около 30 минут, клиенты сохранились [3 польз.] (#96253 #100440 #100722). Если бэкап не создаётся, скопировать вручную `/root/antizapret/config`, `/etc/openvpn/easyrsa3`, `/etc/wireguard` (#96550). Восстанавливать на чистую установку [АВТОР] (#63533).
- Ключи OpenVPN берутся прямо из `/etc/openvpn/easyrsa3`, папки server/keys и client/keys убраны (20.07) [АВТОР] (#91912). Если повреждён `easyrsa3/pki`, хранилище ключей пересоздаётся и старые профили перестают работать [АВТОР] (#98152). 21–22.07 у двух участников OpenVPN-профили из бэкапа не восстановились, автор разбирался, итог неизвестен [2 польз.] (#89653 #89760).
- Перед каждой установкой сохраняйте у себя конфиги клиентов [АВТОР] (#91754).
- Сертификаты: повторное создание клиента продлевает срок, просроченный продлить нельзя; после удаления клиента ребут не нужен [АВТОР] (#60235 #81790 #86981). При общих корневых ключах профиль OpenVPN работает на всех серверах (#84161). Два сервера в pfSense/OPNsense конфликтуют (одинаковый CN у CA): очистить папку easyrsa3 и пересоздать профили через `client.sh`, пункт 7 [АВТОР] (#67318).
- После переезда на новый хостинг DNS отдавал для YouTube реальные IP или NXDOMAIN, помог `systemctl restart kresd@1 kresd@2` [1 польз., не подтверждено] (#94177).

## Ядро 7, DCO и DKMS

- **Главная проблема октября–ноября.** На Ubuntu 24.04 HWE-ядро 7.0.0-38/-42 не даёт DKMS собрать `ovpn-dco` 0.2.20251017. dpkg остаётся в ошибке, setup.sh падает с «Error at line 435/453/460: apt-get dist-upgrade» [АВТОР + 5 польз.] (08.10–02.11; #97727 #97872 #97920 #97922 #98747 #100238 #100636).
  - Решение: `apt remove --purge -y openvpn-dco-dkms` или установка без DCO. DCO для OpenVPN 2.7 уже встроен в ядро 7 и отдельным пакетом не ставится [АВТОР] (#90339 #97727 #97922).
  - Проверка: в выводе `openvpn --version` есть `[DCO]`, строка «DCO version» не N/A [АВТОР] (#69172 #97727). Скрипт `/root/antizapret/openvpn-dco.sh y` (#62555).
- Тот же сбой у `amneziawg-dkms` 1.0.0 (PPA Amnezia, его тянет AZ-AWG2) на ядре 7.0.0-38. Пока фикс не влит в апстрим (issue #259, PR #265), AZ-AWG2 лучше не ставить; правка compat.h от участника не проверена [3 польз.] (#98408 #98415 #98766 #99033).
- После HWE-ядра `kernel.nmi_watchdog` стал только для чтения, и doall/parse.sh падали на `sysctl -p`. 02.11 применение sysctl при обновлении убрано [АВТОР] (#100617 #100627).
- 03.11 в `99-antizapret.conf` добавлено усиление: `kptr_restrict=2`, `bpf_jit_harden=2`, запрет unprivileged userns, `net.mptcp.enabled=0` (уязвимость MPTCP). Получить — повторным setup.sh [АВТОР] (#100808). Участник напомнил, что Go ≥1.24 принимает MPTCP по умолчанию (#100444).
- История: 05.02 — ошибка DCO на `apt-get install --reinstall linux-headers-generic` из-за сломанного репозитория Ubuntu (#62555 #62859); 13.02 — при недоступном build.openvpn.net патченная сборка берётся с GitHub (#64327); 10.03 — OpenVPN 2.7 с новым ядром и DCO (#69172) [АВТОР].

## Стабильность сервера

- Ежедневные ребуты и зависания связаны с OpenVPN TCP (виснет DCO в ядре), отключение TCP-служб помогло [АВТОР + 2 польз.] (#83112 #83534 #87980 #91660).
- Самопроизвольные перезагрузки (крах ядра, найден через kdump): 16.03 отключали TSO/GSO/GRO через ethtool, на одноядерном VPS под нагрузкой проблема не решена [АВТОР + 1 польз.] (#70304 #70458). Сейчас offload не трогается (по коду форка).
- 01.01 исправлен большой цикл опроса интерфейсов, вешавший сервер под нагрузкой, добавлена балансировка SoftIRQ [АВТОР] (#58773 #59279).
- Сервер не принимает новые подключения до ребута — обновите АЗ [АВТОР] (#59886). Баг OpenVPN с CPU 100% описан в [«Протоколах»](protocols.md#openvpn-известные-баги).

## Соседство с другим ПО

- Свои правила iptables кладите в `custom-up.sh` / `custom-down.sh`, потому что up.sh перезаписывается при обновлении. `|| true` гасит ошибку, иначе АЗ не стартует [АВТОР + 1 польз.] (#59713 #99400 #99404 #99406).
- Xray/3x-ui рядом можно, если подсети не пересекаются; при запущенном docker NOTRACK для DNS не ставится [АВТОР] (#59116 #61489).
- ISPmanager ставит bind9, поэтому с 06.06 локальные DNS АЗ живут на 127.1.1.x / 127.2.2.x / 127.3.3.x [АВТОР] (#84329).
- zapret2 рядом с АЗ вызывал лаги [1 польз., не подтверждено] (#91869 #91870). TG-прокси и VLESS на сервер с АЗ ставить не советуют, см. [«Сторонние инструменты»](tools-and-addons.md).
- При SSH-защите setup.sh удаляет fail2ban и sshguard (по коду форка); лимит — 5 подключений в минуту (был 3) [АВТОР] (#65997).
