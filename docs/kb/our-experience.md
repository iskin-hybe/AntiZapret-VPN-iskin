## Сервер

- Хостер AlbHost, тариф «Geolocated AL 1» (6 €/мес): 1 ядро 3,6 ГГц, 4 ГБ RAM, 20 ГБ NVMe, 1 Гбит/с, 10 ТБ трафика, IPv4 + /64 IPv6, KVM, есть AES-NI (2026-11-04).
- «Geolocated» означает, что сервер физически стоит в Нидерландах (Керкраде/Эйгелсховен, датацентр SkyLink), а IP числится за Албанией:
  - **Албания:** RIPE (`country: AL`), geofeed хостера (`/24 → AL, Tirana`), MaxMind, ip-api;
  - **Нидерланды:** ipinfo, ipapi.co, ipwho.is (они вычисляют страну по задержкам).
- Пинг из Москвы (домашний провайдер, Wi-Fi) ~65 мс, разброс ~1,3 мс, потерь 0%.
- Ubuntu 24.04. При установке поставилось HWE-ядро 7.0.0-42. Модуль ядра `ovpn` загружен (DCO работает), патч OpenVPN установлен (`/usr/local/src/openvpn`).

## Установка: что выбрали и что важно

- Установка и ночные обновления идут из форка (`SCRIPTS_REPO`/`LISTS_REPO` в `update.sh`), см. `CLAUDE.md`.

## AdminPanelAZ

- **«Нет активного узла» в «Выдаче VPN-профилей».** Причина: при установке выбран пункт 1 «Только панель». Он ставит `LOCAL_ANTIZAPRET_ENABLED=false`, и панель не видит локальный АЗ. Исправление: `LOCAL_ANTIZAPRET_ENABLED=true` в `/opt/AdminPanelAZ/backend/.env` и `systemctl restart adminpanelaz`. Для одного сервера при установке нужно выбирать пункт 2.
- **Доступ к панели закрыт снаружи.** Панель слушает `0.0.0.0:8080`. Файрвол пускает к ней только `lo` и `10.28.0.0/15`, правила лежат в `/root/antizapret/custom-up.sh` и `custom-down.sh`. Адрес панели: через VPN — `http://10.29.0.1:8080` (OpenVPN) или `http://10.29.8.1:8080` (AmneziaWG/WireGuard); запасной путь — SSH-туннель `ssh -N -L 8080:127.0.0.1:8080 root@<сервер>`.
  - Особенность: `custom-down.sh` снимает эти правила, пока служба `antizapret` остановлена. Поэтому в самой панели рекомендовано включить список разрешённых адресов `127.0.0.1` и `10.28.0.0/15` («Защита входа»). Сначала добавить адреса, потом включать переключатель. Включено ли это на сервере — не подтверждено.
  - Если через сервер ходят посторонние клиенты, правило `10.28.0.0/15` лучше сузить до IP своих устройств.
- **Антисканер панели банит и локальные адреса.** `127.0.0.1` (туннель) и `10.x` (VPN) банятся внутри самой панели, не на файрволе. Если ошибся с паролем — заходить другим путём и снимать бан в «Активные блокировки».
- **Passkeys работают только через `localhost`/HTTPS.** Через `http://10.29.x.1` нужна TOTP-2FA.
- **Что выключено в «Разделах панели»:** Маршрутизация, AZ-WARP, Unlock-коды, Клиентский портал, Планировщик CIDR DB. Генерация и развёртывание CIDR пишет `config/AP-*-include-ips.txt` и меняет маршруты АЗ.

## Мобильный интернет Yota (Мегафон, Москва), 2026-11-04

**Симптом.** На Wi-Fi всё работает. На Yota любой способ подключения к нашему серверу работает около минуты (VLESS — до 32 Мбит/с), потом трафик умирает. После этого Yota примерно на полчаса и дольше душит **весь** трафик к IP сервера: обычный HTTP-файл качается 20–40 КБ/с вместо ~1,6 МБ/с до тестов.

| Что пробовали | Результат |
|---|---|
| AmneziaWG, профиль АЗ, Jc=100 и Jc=5 | плохо / отваливается |
| AmneziaWG, профиль полного VPN | минута, потом отвал |
| OpenVPN UDP с патчем | не подключился |
| Hysteria2, UDP 8443, самоподписанный сертификат | ~0 трафика, timeout |
| VLESS + Reality, TCP 443, SNI www.microsoft.com | ~1 мин 32 Мбит/с, потом отвал и штраф IP |
| VLESS + Reality под свой домен (DuckDNS + Let's Encrypt) | не помогло |
| Обычный HTTP-файл без VPN (до тестов VPN) | 21 МБ за 13 с — сам IP не заблокирован |
| Платный VPN «Обход глушилок» (Hysteria2, VLESS TLS/Reality) | работает стабильно |

**Выводы.**
- Дело не в протоколе и не в маскировке. Похоже на поведенческий детект с последующим штрафом IP. В чате ~8 человек описывали временные баны IP на Yota/Билайне, см. `mobile-and-blocking.md`.
- AmneziaWG без строки `I1` и с `Jc=4, Jmin=40, Jmax=70` (рецепт из чата для Мегафона и Yota) — тоже ~20 с нормально, потом тормоза (2026-11-05). Параметры AWG не решают.
- Вход через российский релей — см. раздел ниже.

## Российский релей (Firstbyte, Москва), 2026-11-05

Релей: Firstbyte (AS204997), тариф 1 ядро / 1 ГБ / 20 ГБ, 189 ₽/мес. Канал ~187 Мбит/с внутри РФ и ~164 Мбит/с во Францию.

**1. `proxy.sh` + AmneziaWG через релей.**
- Установка штатная: 12 правил DNAT и SNAT. IP релея добавлен в `allow-ips.txt` основного сервера **с маской `/32`**, иначе `parse.sh` строку отбрасывает; затем `parse.sh ip`.
- **На Wi-Fi работает отлично**, значит, плечо релей → основной сервер в порядке.
- **На Yota — ~150 Кбит/с с первой секунды.** Подсчёт пакетов на релее (`tcpdump`) показал, что релей пересылает всё без потерь в обе стороны. Режет участок Yota → релей, хотя релей российский: AmneziaWG у нас маскирует только рукопожатие, данные идут в формате WireGuard.
- После этого **Yota оштрафовала и адрес релея**: обычный HTTP-файл с релея на Yota — 5–10 КБ/с, на Wi-Fi — мгновенно. Вывод: с мобильной Yota к релею не подключаться через AmneziaWG/WireGuard, иначе адрес «сгорает».

**2. VLESS + Reality на релее, выход через WireGuard в полный VPN основного сервера.**
- Скрипт: [`tools/relay-vless.sh`](../../tools/relay-vless.sh). Релей — обычный клиент полного VPN (`client.sh 4 relay`). Трафик Xray помечается (`sockopt.mark`) и уходит в туннель через отдельную таблицу маршрутов; SSH и `proxy.sh` идут как раньше. Свой домен релея (DuckDNS) и настоящий сертификат Let's Encrypt для маскировки.
- **Туннель релей → основной сервер (обычный WireGuard) быстрый:** ~158 Мбит/с во Францию через туннель. Плечо Firstbyte → Нидерланды WireGuard не режет.
- **Ловушка с отпечатком TLS:** с `fp=chrome` (а также `safari`, `ios` в INCY) на домашнем МТС соединения застревали — от телефона доходил ровно один пакет на 1440 байт, а продолжение приветствия терялось. Диагностика на релее:
  ```bash
  ss -tniH state established '( sport = :443 )' | grep -oE 'bytes_received:[0-9]+' | sort | uniq -c | sort -rn | head
  ```
  Много строк `bytes_received:1440` — признак проблемы. Обычный HTTPS с маленьким приветствием (`curl` с Mac) и загрузка 5 МБ на релей проходили. Вероятная причина — большое приветствие с постквантовым ключом (ML-KEM, ~1,8 КБ, два пакета) не проходит фильтр на пути.
- **С `fp=firefox` в INCY — 0 застрявших из 40, YouTube летает (Wi-Fi).** `edge` в INCY не подключился вовсе. Отпечаток надёжнее зашивать в саму ссылку: смена в настройках INCY, похоже, не применялась.
- **VLESS-firefox на Yota через свежий релей** (второй VPS Firstbyte, адрес Yota до этого не видела, AmneziaWG не использовали): ~1 минуту летает, потом трафик умирает. Застрявших рукопожатий нет (0 из 100–380 соединений), но соединения копятся — приложения переподключаются. **Сразу после этого обычный HTTP-файл с нового релея на Yota качается медленно** — адрес оштрафован (2026-11-05).

## Платный VPN, который работает на Yota: откуда его входы (2026-11-06)

Выяснили, к каким адресам подключается клиент платного VPN с режимом «Обход глушилок». На Mac смотрели `lsof` при подключении к каждому серверу из подписки, на iPhone — отчёт о конфиденциальности приложений. Владельцев сетей — через RIPEstat. Адреса намеренно не приводим.

| Сервер в подписке | Транспорт | Сеть входа |
|---|---|---|
| Обход глушилок 1 | VLESS TCP Reality | Crea Nova Hosting, Финляндия |
| Обход глушилок 2 | VLESS WebSocket TLS | DDoS-Guard, российский анти-DDoS-прокси и CDN: телефон видит адрес DDoS-Guard, а не сервера |
| Обход глушилок 3 | VLESS gRPC Reality | похоже, тот же адрес в Финляндии (не точно) |
| Обход глушилок 4 | Hysteria | Private Layer, Швейцария (в `lsof` видны TCP-соединения на 443) |
| Обход глушилок 5 | VLESS TCP TLS | Data Room, Румыния |

- На iPhone на LTE приложение VPN чаще всего обращалось к домену в Нидерландах (маленькая частная AS, адреса арендованы у литовского брокера) и к тому же швейцарскому адресу. Реже — к российскому хостингу Kontel (Москва) и FairyHosting (Эстония).
- При каждом подключении было по одному соединению в Cloud.ru (российское облако). Похоже на служебный трафик приложения, а не на туннель (не проверено).
- Вывод пока предварительный: входы — в основном обычные мелкие хостинги, плюс один вариант через российский CDN. Каких-то «белых» адресов в основе схемы не видно. По словам владельца, на телефоне на Yota нормально работают все серверы «Обход глушилок» (2026-11-06).

### Как выглядит их подключение (запись трафика на Mac, «Обход глушилок 1», 2026-11-06)

- **В ClientHello нет SNI вообще.** Клиент подключается по IP, расширения server_name нет. У нас в SNI был домен DuckDNS (свой домен под self-steal), а в тестах на основном сервере — чужой сайт.
- **Отпечаток — Firefox** (без GREASE, delegated_credentials, record_size_limit) **с постквантовым ключом X25519MLKEM768.** ClientHello 1866 байт уходит двумя обычными TCP-сегментами (1384 + 482). Никакого искусственного дробления на мелкие куски нет. Сервер выбирает X25519MLKEM768 (ServerHello 1210 байт). Значит, большой ClientHello сам по себе не мешает. Застревание на 1440 байтах у нас на домашнем МТС было, вероятно, из-за отпечатка Chrome или SNI, а не из-за размера.
- **Сервер — REALITY**: сертификат в ответе ~3,4 КБ (REALITY подгоняет длину под сертификат сайта-цели).
- **Соединения короткие, по одному TCP на каждое соединение приложения:** 121 соединение за ~25 с, медиана жизни 12 с. Самое большое за запись — ~5 МБ. Мультиплексирования нет.
- **Гипотеза:** ТСПУ проверяет SNI — совпадает ли домен с IP, не подозрительный ли он (динамический DNS). Без SNI проверять нечего. Проверка — тот же релей, но ссылка по IP без SNI (`tools/relay-vless.sh` теперь выдаёт такую основной).

## Как мы проверяли (повторяемые приёмы)

- **Временный файл для теста скорости без VPN:**
  ```bash
  mkdir -p /tmp/dl && head -c 20M /dev/urandom > /tmp/dl/test.bin && cd /tmp/dl && timeout 600 python3 -m http.server 8090
  ```
  Потом открыть `http://<IP>:8090/test.bin` с телефона.
- **Кто в бане у защиты АЗ:** `ipset list antizapret-block | grep -E '^[0-9]+\.'`. Владельца адреса смотреть через RIPEstat (`stat.ripe.net/data/prefix-overview`).
- **Страна IP:** RIPE whois, geofeed хостера, несколько гео-баз. Решающее — что видит Google: страна внизу google.com и код страны у логотипа YouTube через VPN.
- **Скорость туннеля в режиме АЗ:** speedtest идёт мимо VPN, поэтому скорость смотреть в «Статистике для сисадминов» 4K-ролика на YouTube.
