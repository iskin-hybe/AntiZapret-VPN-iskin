## Как АЗ решает, что пускать в туннель

- Заблокированные домены DNS АЗ отдаёт как фейковые IP из одной подсети (по умолчанию `198.18.0.0/15`). Отдельные маршруты добавляются только для IP-списков. Новый домен начинает работать через DNS, маршруты для него менять не нужно [АВТОР] (#59813, #83361, #89751, #93184).
- Итоговый список доменов лежит в `/root/antizapret/result/include-hosts.txt` [АВТОР] (#89751).
- OpenVPN получает IP-маршруты от сервера через push при каждом подключении (предел около 2 тыс.). В WG/AWG маршруты записаны в `AllowedIPs`. После изменения IP-списков WG-профили нужно скачать заново или поправить маршруты на роутере вручную [АВТОР + 2 польз.] (#86791, #89429, #80092, #92709, #95509, #93067).
- Списки обновляются ночью сами. Чтобы применить правку в `config/` сразу, запустите `doall.sh` (или `parse.sh`) [АВТОР] (#59692, #95567, #100646).
- По просьбе автор бесплатно добавляет в общий список до 5 сайтов. Берёт только популярное, «мусорные» домены (Xiaomi, duckdns, haylou) не добавляет [АВТОР] (#78222, #75358, #61665, #60679).
- Из списков убирают то, что уже не блокируется: reddit, gmail.com, letsencrypt.org, duckdns.org, gvt2/gvt3. gvt1.com вернули: без него не обновлялся Google Play [АВТОР] (09–10.26, #93026, #93054, #95008, #100654).

## Файлы в `config/`: форматы и приоритеты

- `include-hosts.txt` — только домены, без IP. Запись действует на домен со всеми поддоменами; строка `.` означает «все домены» (см. шапку файла) [АВТОР] (#83725).
- `exclude-hosts.txt` приоритетнее include [АВТОР] (#61819, #62235).
  - По словам автора, исключение действует, только если домен попадает в include (#75559, #70325, 04.26).
  - Шапка файла в текущем репозитории: «исключить можно любые домены, а не только добавленные в download/include-hosts.txt». Это важно при ROUTE_ALL.
- `remove-hosts.txt` убирает запись из общего списка целиком; поддомены при этом не затрагиваются. Рецепт автора: чтобы google.com шёл напрямую, а notebooklm через АЗ, положите google.com в remove-hosts [АВТОР] (#79242, #83725, #88445).
- `include-ips.txt` — только подсети в CIDR, одиночный адрес пишется как `/32`. Обрабатываются все файлы `config/*include-ips.txt` и `*exclude-ips.txt`, так что свои файлы можно называть с префиксом [АВТОР] (#66680, #69565).
- `exclude-ips.txt` убирает только запись, в точности совпадающую с записью из include, а не часть подсети [АВТОР] (#61819, #62235, #83725).
- `include-ips` попадает в конфиг и в push. `forward-ips.txt` в push не попадает. Оба файла разрешают форвардинг [АВТОР] (#98031, #99015, #99016).
- Файлы с апреля–мая [АВТОР]:
  - `drop-ips.txt` — подсети, которые запрещено форвардить (27.04, #79736);
  - `deny-ips.txt` — блок входящих подключений к серверу; автор внёс туда только подсети ФГУП ГРЧЦ AS61280/AS213853 (05.05, #80800, #81966);
  - `allow-ips.txt` — исключения из защиты от сканирования и атак (ipset `antizapret-allow`). Автор говорил «только /32» (#91907), но в текущем `up.sh` ipset имеет тип `hash:net`, то есть маски допустимы.
- Если домен резолвится в `0.0.0.0`, он попал в адблок. Правьте `exclude-adblock-hosts.txt` / `include-adblock-hosts.txt` [АВТОР] (#69006, #70795).
- Привязка домена к IP через RPZ описана в [dns.md](dns.md#свои-переопределения-customlua-и-rpz).

## ROUTE_ALL — все домены, кроме RU

- Опция `ROUTE_ALL` («Route all domains via AntiZapret VPN, excluding Russian domains and config/exclude-hosts.txt»), по умолчанию `n`. С 02.03 автор предлагает её вместо удалённых IP-списков хостеров [АВТОР] (#67641, #67639, #67939, #90355).
- Плюсы и минусы. Автор (01.26): при массовых блоках по IP так проще. Игры, которые ходят по IP, всё равно идут мимо. Один пользователь: работает, но медленнее [АВТОР + 1 польз.] (#60922, #60953).
- На TP-Link Archer AX73 не влезает конфиг примерно с 650 маршрутами. Включите ROUTE_ALL и не добавляйте лишние include [АВТОР] (#67601, #67613).

## WARP

- **Режимы для АЗ (`ANTIZAPRET_WARP`)** [АВТОР] (#94575, #96613, #96614, #98763, #100176):
  - 1 None — выключен; 2 All — весь трафик, exclude не работает;
  - 3 Domain — домены АЗ плюс `include-warp-hosts` минус `exclude-warp-hosts`; IP в этом режиме пока не маршрутизируются;
  - 4 Custom (по умолчанию) — только `config/include-warp-hosts.txt`; в нём STUN-серверы и cloudflare.com.
- **Режимы для полного VPN (`VPN_WARP`)**: 1 None, 2 All (по умолчанию), 3 Custom. Автор советует полный VPN только через WARP: так не виден IP сервера и меньше шанс бана [АВТОР] (#75547, #93005, #100979).
- **Списки `include-warp-hosts.txt` и `exclude-warp-hosts.txt` общие для АЗ и полного VPN** (по коду `parse.sh`, 2026-11-05). Если вписать в include точку `.` (все домены) ради полного VPN, то у АЗ-клиентов тоже все домены, включая российские сайты и банки, пойдут через сервер и WARP: резолвер АЗ проверяет `warp.rpz` раньше списка блокировок. «Весь полный VPN через WARP, кроме YouTube» настройками не сделать: в режиме All исключения не работают, а в Custom список общий. Нужна правка `parse.sh` с отдельными списками для полного VPN.
- **WARP protection (`WARP_PROTECTION`, по умолчанию `y`).** Если WARP не поднялся (API не вернул endpoint, в конфиге пустой endpoint), трафик VPN блокируется, чтобы не засветить IP сервера. В конфиг опция ничего не пишет. Сам WARP подключается через маршрут по умолчанию, проверка: `ip route get $(dig engage.cloudflareclient.com +short)` [АВТОР] (#94611, #94615, #94619, #94620, #96635).
- **Свои ключи** задаются в setup: `ANTIZAPRET_WARP_*` и `VPN_WARP_*` (`PRIVATE_KEY`, `PUBLIC_KEY`, `ENDPOINT`, `ADDRESS`). Для АЗ и VPN нужны два разных ключа, после правки — ребут [АВТОР] (#92426, #92872). Вместо WARP можно вписать данные Proton, но при обновлении настройка слетит, а один конфиг Proton нельзя использовать на нескольких VPS [АВТОР + 1 польз.] (#94144, #94150, #99181).
- **Ограничения** [АВТОР] (#64860, #66342, #77461, #77618, #88982): около 10 тыс. conntrack-подключений — примерно 10 человек нормально, 50 тормозит. Страну выхода не выбрать: эндпоинт anycast, выход в стране входа, поэтому серверу в РФ WARP не поможет. Хорошо работает, когда до эндпоинта около 1 мс.
  - Через WARP не работают Twitch (usher.ttvnw.net) и Gemini. Пускает ли Battle.net, зависит от локации WARP (#76504–#76513). YouTube через WARP видел регион GB (#65649, #65675).
- **История** [АВТОР]: 17.02 — опция «WARP для всего исходящего трафика» (#65572); 08.04 — отдельно для АЗ и полного VPN (#76228); 20.04 — для полного VPN выключен по умолчанию (#79113); 20.07 — отдельные WARP-подключения для АЗ и VPN, с 11.08 «не тормозит» (#89551, #91624); 27.08 — выборочная маршрутизация по доменам (#93295); 10.10 doall стал переподключать WARP, 02.11 это убрали, сейчас в setup `RECONNECT_WARP=n` (#98061, #100591); 27.10 от зависаний отключены TCP timestamps; 02.11 фейк-IP переведены на nftables, WARP исправлен (#99702, #100591).
  - Пользователи в 09–10.26 жаловались: после ночного `wg-quick down/up` WARP переставал отвечать, домены через WARP работали минут 5 после переустановки, помогал перевыпуск ключей [3 польз.] (#98254, #98263, #99631). Подтверждения, что фикс 02.11 это исправил, пока нет.
- Интерфейсы — `warp-antizapret` и `warp-vpn`, конфиги в `/etc/wireguard/`. Раньше был один `/etc/wireguard/warp.conf`: его генерирует `up.sh`, и меняется он только при рестарте сервиса или сервера (#76504, #76799). MTU WARP см. в [troubleshooting.md](troubleshooting.md).
- Не планируется: маршрутизация по доменам в разные выходы (sing-box). В планах: роутинг IP в режиме 3 и исключения для полного VPN через WARP [АВТОР] (#64864, #65892, #77902, #94059, #96614).

## Изоляция клиентов, RESTRICT_FORWARD, связь между клиентами

- `CLIENT_ISOLATION` («all VPN client and server isolation») включена по умолчанию с 10.01. Клиенту на сервере видны только DNS:53 и ping. Разделять изоляцию клиентов и сервера автор не будет [АВТОР] (#59466, #67255, #67266).
  - Домен сервера резолвится у клиентов в 10.29.x → смените hostname или отключите изоляцию (#69861, #69887).
  - Нужен свой доступ к сервису на сервере → удалите правила `INPUT DROP` в `up.sh` или в `custom-*.sh` (#67270).
- `RESTRICT_FORWARD=y` (по умолчанию): АЗ форвардит только на адреса из `config/forward-ips.txt` и `result/route-ips.txt`. На вопрос установщика автор советует оставить значение по умолчанию [АВТОР] (#59532, #100795).
  - Маршруты на роутере прописаны вручную (MikroTik) → отключите опцию или добавьте подсети в forward-ips (#60184).
- Чтобы клиенты видели друг друга, отключите изоляцию и добавьте подсети клиентов в include-ips (в 01.26 автор советовал forward-ips). Если 10.x конфликтует с локальной сетью, выберите альтернативный диапазон клиентов 172.x (`ALTERNATIVE_CLIENT_IP`) [АВТОР] (#59532, #89080, #91548, #99410). Пользователи задают клиенту статический IP через ccd `ifconfig-push` и пробрасывают порт на роутере (#91515, #91534).
- Клиенты за промежуточным сервером приходят с одного IP и попадают под защиту. Внесите этот сервер в исключения (`allow-ips.txt`) [АВТОР] (#89181).

## Свои правила: custom-*.sh и выходной интерфейс

- `up.sh` перезаписывается при обновлении. Свои правила iptables кладите в `custom-up.sh`, их удаление — в `custom-down.sh`. Хуки вызываются с `|| true`, иначе ошибка в них не даёт АЗ стартовать [АВТОР] (#59713, #99400, #99404, #99406). Есть также `custom-doall.sh`, `custom-parse.sh`, `custom-update.sh`, а для OpenVPN — `custom-client-connect.sh` и `custom-client-disconnect.sh`. Файлы `custom*` попадают в бэкап (#88075, #99234).
- Выходной интерфейс и IP задаются переменными `ANTIZAPRET_OUT_INTERFACE/IP`, `VPN_OUT_INTERFACE/IP` и `DEFAULT_INTERFACE/IP` (с 22.04; раньше `OUT_INTERFACE=`/`OUT_IP=`) [АВТОР] (#79212, #84140, #75309).
  - Маршруты на свой интерфейс (например, xray0) автоматически не добавляются (#75321).
  - Входящие подключения на выходные IP блокируются; нужный IP должен быть основным в `/etc/network/interfaces`. 26.09 автор советовал при заданных выходных IP отключать WARP (#96318, #96611, #99440).
  - Второй IP на том же VPS от блокировок не спасёт: AS та же (#70382).
  - Пользователь пустил трафик АЗ с RU-VPS через wg-туннель на зарубежный VPS, ip rule не понадобился (#79239) (1 польз., не подтверждено).
